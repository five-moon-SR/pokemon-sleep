## 1. 料理パワーアップS

### Lv別効果量（なべ容量 +N個）

| Lv | 効果量 | 出典 |
|----|--------|------|
| 1 | 7 | https://wikiwiki.jp/poke_sleep/メインスキル/料理パワーアップ |
| 2 | 10 | 同上 |
| 3 | 12 | 同上 |
| 4 | 17 | 同上 |
| 5 | 22 | 同上 |
| 6 | 27 | 同上 |
| 7 | 31 | 同上（最大Lv=7。data/main_skill.json の max_level:7 と一致） |

### 仕様メモ
- 効果は「次回の料理」に対して発動するもので、消費されるまで**リサーチフィールド移動・週跨ぎをしても維持される**（料理チャンスSと違い持ち越し型）。
  > 「増やしたなべの容量は、リサーチフィールドを移動したり、週を跨いだりしても維持される。」（https://wikiwiki.jp/poke_sleep/メインスキル/料理パワーアップ）
- **重ねがけ可能**。複数体編成・スキルストック等で発動を重ねると容量増加は加算され、上限は+200個。
  > 「重ねがけでき、最大200個まで増やすことができる。」（同上）
- なべ容量を+200の上限まで増やした状態でさらに発動しようとすると、発動不可の通知が出て解消（料理する）まで再発動できない。
- **日曜日のなべ容量2倍ボーナスは、本スキルによる増加分には及ばない**（元の基礎容量だけが2倍になる）。
  > 「日曜日にはなべの容量が2倍になる仕様があるが、本スキルによる増加分は倍化の対象にはならない。」（同上）
- いいキャンプチケット使用中は、チケットの「なべ容量1.5倍」効果が本スキルの増加分にも及ぶ（＝(基礎容量×日曜2倍+スキル増加分)×1.5、の順で計算例あり）。
- 効果は「使われるまで持続」であり、料理を1回行うとその回の料理でリセットされる（＝1回分の料理にしか効かない。次の料理には持ち越されない）。

### 仕様メモ
- 基本効果（なべ容量+N）は料理パワーアップSと同一の重ねがけ・持続仕様（フィールド移動・週跨ぎで維持、消費されるまで持続）。
- げんき回復の追加効果が発動する条件は「特定の条件」ではなく明確に**「自分以外にメインスキル『プラス』か『マイナス』を持つポケモンがチームに1匹以上いること」**。
  > 「自分以外に、メインスキル『プラス』か『マイナス』を持つポケモンがチームに1匹以上いる場合、さらにランダムで、チームのポケモン1匹のげんきをM回復する」（同上）
- 単体運用時は素の料理パワーアップSより効果量が低いため、基本的には追加効果（プラス/マイナス同時編成）を狙う運用が前提とされている。

## 3. 料理チャンスS（最重要：累積・持続仕様）

### Lv別効果量（大成功確率 +N%）

| Lv | 効果量 | 出典 |
|----|--------|------|
| 1 | 4% | https://wikiwiki.jp/poke_sleep/メインスキル/料理チャンス |
| 2 | 5% | 同上 |
| 3 | 6% | 同上 |
| 4 | 7% | 同上 |
| 5 | 8% | 同上 |
| 6 | 10% | 同上（最大Lv=6。max_level:6 と一致） |

### 仕様メモ（累積・持続・リセット条件）
- **累積は加算式**。同一ポケモンの複数回発動、複数体編成、いずれでも上がった大成功確率は**足し算で積み上がる**（＝「1体分の効果しか乗らない」という仕様ではない）。
  > 「料理の大成功確率アップの効果は最大+70%まで重ねることができる。」（同上）
- 上限は **+70%**。上限を超える分は切り捨て。
  > 「スキル効果量が上限（+70%）を超える場合、上限を超えた部分は切り捨てになる。例えば+62%の状態でスキルレベル6（+10%）が発動すると、8%上がったと表示される。」（同上）
- 効果が既に+70%に達している状態で発動しようとすると、発動不可のポップアップが出て**発動そのものがキャンセルされる**（スキルストックで2回同時発動時は上限超過分だけ無駄撃ちになり、ポップアップは出ない）。
- **持続条件**：「料理の大成功が発生する」または「フィールドを移動する」までは持続する。これ以外（例えば料理を作っても大成功しなかった場合や、週をまたぐだけで同フィールドに留まる場合）ではリセットされない。
  > 「効果は料理の大成功、またはフィールド移動でリセット。」（同上）
- **料理パワーアップSと異なり、週を跨いだだけ／フィールド移動では効果が消えてしまう**（＝週跨ぎで持ち越されるのはパワーアップS側の仕様であり、料理チャンスSは対象外）。
  > 「週を跨いだり島を移動してもメインスキルの料理パワーアップは効果を引き継がれるが、料理チャンスは効果が切れてしまう」（同上）
  - 例外的な小技として、「効果が+70%上限に達し発動不可（＝未発動状態）」のままなら、その未発動状態自体は週を跨いで持ち越せる、という運用（通称「料理チャンス持ち越し」）が紹介されている。これはスタック済み%の持ち越しではなく、「スキル発動待機状態」の持ち越しである点に注意。
- 平日の最大到達確率は「基本10% + 料理チャンス上限70%」＝**80%**、日曜は「基本30%（後述） + 70%」＝**理論上100%**。
  > 「平日の最大80％（料理チャンス効果上限70％＋基本値の10％）は…」（同上）

### 効果量の評価（考察セクションより）
- 重ねがけ（同一プレイ内で複数回発動）するほど、メインスキル1回あたりの獲得エナジー期待値は逓減する（Lv6を1回・2回・3回発動時の1回あたり期待値は49.81%→33.34%→25.0%、と低下）。ただし下振れリスクは減る。
- 発動タイミングが早いほど（月曜朝食前など）獲得エナジー期待値は高く、日曜夕食前など終盤の発動は期待値が低い。
  > https://wikiwiki.jp/poke_sleep/メインスキル/料理チャンス（考察 / 期待値によるスキル効果の評価）

## 5. 大成功の基礎仕様（料理チャンスS/ビルドアップの前提）

出典: https://wikiwiki.jp/poke_sleep/料理

- **基礎の大成功確率**：月〜土は10%、日曜は30%。
  > 「基本的な大成功率は10%なのではないかと考えられる」「月～土: 大成功倍率2倍・大成功確率10%／日: 大成功倍率3倍・大成功確率30%」
  - 日曜の30%は「基本10% + 日曜ボーナス+20%」の合算として説明されている。
  - ※Wiki自身も「～と考えられる」という推測込みの検証結果（データ収集による逆算）であることに注意。実測データでは「大成功頻度が異常に高い/低い場合がある」ため、隠し要素の存在も示唆されている（未確定）。
- **大成功時のエナジー倍率**：平日2倍、日曜3倍。
  > 「大成功時のエナジーについて：平日は2倍・日曜は3倍になるが、エナジーの数値は2の倍数・3の倍数になるとは限らない。」
- 連打（同じレシピを繰り返し作る）すると大成功率がやや下がるというデータがある、との言及あり（詳細未確定、`検証/料理の大成功` 参照との案内のみで具体的な下がり幅は未取得）。

### 6.2 `utils/plan_simulation.py`（本題：複数体の扱いと大成功確率の上限）

1. **料理チャンスS/料理アシストの複数体加算 → `max()` 問題（ユーザー指摘の論点）**
   - 該当コード（231-236行目）:
     ```python
     if category == "料理パワーアップS":
         pot_acts += acts
         pot_effect = max(pot_effect, effect)
     elif category in {"料理チャンスS", "料理アシスト"}:
         chance_acts += acts
         chance_effect = max(chance_effect, effect if category == "料理チャンスS" else 1.0)
     ```
   - **判定：不正確。ただし「1体分しか見ていない」わけではなく、方向としては過大評価になりやすい。**
     - `chance_acts`（発動回数）はチーム内の全 料理チャンスS/ビルドアップ 保有ポケモンの発動回数を**合算**している。つまり「発動頻度」自体は複数体分を正しく積み上げている。
     - 一方で `chance_effect`（1回あたりの%）は複数体の中の**最大値だけ**を採用し、その最大値を全発動回数に一律適用している（`chance_bonus += chance_acts * chance_effect / 100.0 * fraction`）。
     - 実仕様は「各ポケモンが自分のスキルレベルの%を持ち寄って加算」（`Σ(acts_i × effect_i)`、上限+70%）。コードの近似は `(Σacts_i) × max(effect_i)` であり、数学的に `Σ(acts_i × effect_i) ≦ (Σacts_i) × max(effect_i)` が常に成立するため、**チーム内のスキルレベルにばらつきがあるほど実際より多く見積もる（過大評価）方向のバイアスを持つ**。全員が同じレベルの場合のみ一致する。
     - さらに `料理アシスト` は本来 Lv1〜7 で+1〜5%と変動するにもかかわらず、コード上は一律 `1.0`（+1%相当）に固定されている。Lv4以上のビルドアップ保有ポケモンがいる場合、実際の寄与（+3〜5%）を過小評価する（こちらは逆方向で過小評価）。
   - 結論：ユーザーの懸念（複数体編成時の扱い）は妥当だが、「1体分しか見ていない」という表現は不正確。実態は「発動回数は合算するが、効果%は最大値で代表させ、かつビルドアップの%は定数1%に固定」という二重の近似で、ネットでどちらに転ぶかはチーム構成次第（レベルばらつきで過大、ビルドアップ混在で過小）。

2. **大成功確率の上限の実装が実仕様とズレている（新規に確認できた差分）**
   - 該当コード:
     ```python
     BASE_GREAT_CHANCE = 0.10
     MAX_GREAT_CHANCE = 0.70
     ...
     chance_bonus = min(MAX_GREAT_CHANCE - BASE_GREAT_CHANCE, chance_bonus + ...)
     great_chance = min(MAX_GREAT_CHANCE, BASE_GREAT_CHANCE + chance_bonus)
     ```
   - これは「大成功確率の**合計**が70%を超えない」という実装になっている（bonusの実質上限を60%に丸めている）。
   - しかしWiki仕様では「**料理チャンス由来のボーナス自体**が最大+70%」であり、これは基礎確率（平日10%/日曜30%）に対する**加算**なので、合計の理論上限は平日80%・日曜100%になる（Wikiの「平日の最大80%」「理論上の最大確率は100%」という記述と一致）。
   - つまり `MAX_GREAT_CHANCE = 0.70` を「合計確率の上限」として使っている現在の実装は誤り。正しくは「ボーナス単体の上限が0.70」であり、合計上限は `BASE_GREAT_CHANCE + 0.70` にすべき。
3. **曜日（日曜）の扱いが未実装**
   - `plan_simulation.py` は `for day in range(7)` のループ内で曜日固有のボーナスを一切参照していない（grep で `day ==` 等の分岐なし）。
   - 実際は日曜に「なべ容量2倍」「大成功時エナジー3倍」「大成功基礎確率30%（10%+20%）」という3つの固有ボーナスがあり、Wikiの考察でも「日曜鍋パ」という主要な運用戦略として扱われるほど影響が大きい。現状のシミュレーションはこれらを一切モデル化しておらず、日曜恩恵を織り込んだ週間エナジー試算（特に料理パワーアップSを日曜に温存して月曜に叩き込む運用）を過小評価する。

## 7. 不明点リスト

- 大成功の基礎確率10%（平日）/30%（日曜）は、Wiki自身が「検証データからの逆算による推測」と明記しており、運営による公式数値ではない。**不明（推測値）**。
- 「連打すると大成功率がやや下がる」現象の具体的な下がり幅・条件は `検証/料理の大成功` 個別ページへの誘導のみで、本調査では未取得（未掲載扱い）。
- 「料理チャンスS」「料理アシスト」のLv別効果量表について、Lv7以上（max_level超）のデータは存在しない（両スキルともゲーム側の上限がLv6/Lv7までのため、これは仕様上「なし」であり欠落ではない）。

- マイナスの「特定の条件」の正確な範囲（プラス/マイナス以外の食材ゲットS系ポケモンが条件に含まれるか等）はWiki記述上「プラスかマイナスを持つポケモン」のみと明記されており、それ以外の条件パターンは**不明（記載なし＝対象外と判断）**。
