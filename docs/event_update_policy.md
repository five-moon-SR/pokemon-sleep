# イベント情報更新ルール

Pokemon Sleep のイベント・新規追加情報をアプリに入れるときの作業ルール。

## 目的

- 直近イベントで変わる捕獲優先度・料理優先度・育成方針をアプリ判断に反映する。
- 新ポケモン、新料理、新フィールド、出現ピックアップ、ボーナス条件を取りこぼさない。
- 公式の確定情報と攻略サイトの推測を混ぜない。

## 優先ソース

1. 公式サイト
   - `https://www.pokemonsleep.net/news/`
   - イベント期間、対象フィールド、ボーナス、初登場ポケモン、公式名称を確認する。
2. ポケモンスリープ攻略・検証 Wiki
   - レシピ一覧、ポケモンマスター、フィールド出現、仕様数値の確認に使う。
   - アプリ内データ更新スクリプトの主ソース。
3. Game8 / ポケらく等の攻略サイト
   - おすすめポケモン、イベント優先度、捕獲方針の補助材料として使う。
   - 未確定・予想表記はデータ化せず、必要ならメモ扱いにする。

## 取る情報

- イベント名
- 開始日時、終了日時、日付境界
- 対象フィールド
- 対象睡眠タイプ、出現しやすいポケモン
- 初登場ポケモン、進化系統、出現フィールド
- 新料理、新食材、新レシピの材料数、エナジー
- 鍋容量、料理大成功、スキル発動、ゆめのかけら、EXPなどのボーナス
- 週ごとのおすすめ行動
- 既存アプリデータとの差分

## 更新判断

- 公式に明記されたものは、イベントメモまたは恒久データとして反映してよい。
- Wikiのマスター・レシピ・出現表に載ったものは、既存スクリプトで取り込む。
- 攻略サイトだけにある予想・リーク・未確認値は、恒久データに入れない。
- イベント限定出現と常設出現は分ける。常設の `field_encounters.json` にイベントピックアップを混ぜない。
- 日付が未来のイベントは、開始前なら「予定」として扱い、通常計算には混ぜない。

## 作業手順

1. 公式ニュースでイベント概要と日付を確認する。
2. Wikiでマスター、料理、出現表の更新有無を確認する。
3. 必要に応じて以下を実行する。
   - `scripts/fetch_wiki_master.py`
   - `scripts/fetch_wiki_master.py --probs`
   - `scripts/fetch_field_encounters.py --apply`
   - `scripts/build_recipe.py`
4. 攻略サイトで捕獲・料理・育成の優先度コメントを確認する。
5. アプリに入れる内容を「恒久データ」「イベント限定メモ」「未反映メモ」に分ける。
6. テストを実行してから push する。

## 報告フォーマット

- 追加・更新したデータ
- 既に最新だったデータ
- 未追加にした情報と理由
- イベント期間
- 参照URL
- 実行した検証

## 今の直近方針

- 最優先はジンジャー担当の確保。
- 狙いはヨーギラス系統。
- ヒーラー更新や他食材補強は重要だが、ジンジャー人材不足の解消を先に見る。
